Question 1 (Easy):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that designs a domain model `BankAccount` and builds an automated unit test suite using standard library `unittest`:
1. Domain Model Specification (`BankAccount`):
   - `__init__(account_holder: str, initial_balance: float = 0.0)`: Initializes account; raises `ValueError` if `initial_balance < 0`.
   - `deposit(amount: float) -> float`: Adds amount to balance and returns new balance; raises `ValueError` if `amount <= 0`.
   - `withdraw(amount: float) -> float`: Subtracts amount from balance and returns new balance; raises `ValueError` if `amount <= 0`, or raises custom `InsufficientFundsError` if `amount > balance`.
   - `balance`: Read-only property returning current funds.
2. Test Suite Implementation (`TestBankAccount(unittest.TestCase)`):
   - Test method `test_initial_balance_valid`: Asserts balance equals initialized amount.
   - Test method `test_initial_balance_negative`: Uses `assertRaises(ValueError)` to verify negative initial deposits fail.
   - Test method `test_deposit_success`: Verifies balance increments correctly after multiple deposits.
   - Test method `test_deposit_invalid_amount`: Asserts zero or negative deposit raises `ValueError`.
   - Test method `test_withdraw_success`: Asserts withdrawal decrements balance accurately.
   - Test method `test_withdraw_insufficient_funds`: Asserts `InsufficientFundsError` is raised when overdrawing.
3. Programmatic Test Runner:
   - Loads test cases via `unittest.TestLoader().loadTestsFromTestCase(...)`.
   - Executes tests using `unittest.TextTestRunner(verbosity=2)`.
   - Programmatically inspects the `TestResult` object: verifies `testsRun`, `failures`, `errors`, and `wasSuccessful()`.

Sample Input:
# Programmatic test execution
suite = unittest.TestLoader().loadTestsFromTestCase(TestBankAccount)
runner = unittest.TextTestRunner(verbosity=0)
result = runner.run(suite)

# Inspect outcomes
total_ran = result.testsRun
was_success = result.wasSuccessful()
fail_count = len(result.failures)
err_count = len(result.errors)

Expected Output:
Tests Run: 6
All Tests Passed: True
Failures Count: 0
Errors Count: 0
Execution Status: SUCCESS

Constraints & Edge Cases:
- Floating point balance operations must be tested using `assertAlmostEqual(actual, expected, places=2)` to prevent IEEE-754 precision mismatches.
- Tests must be completely self-contained; test execution order must not affect outcomes.

Question 2 (Easy-Intermediate):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that designs a File-Backed Cache Manager `PersistentFileCache` and constructs a comprehensive test fixture harness demonstrating `setUp`, `tearDown`, `setUpClass`, `tearDownClass`, and `addCleanup`:
1. System Under Test (`PersistentFileCache`):
   - `__init__(cache_dir: str)`: Creates directory if non-existent.
   - `set(key: str, data: dict[str, Any], ttl_seconds: float = 3600.0) -> None`: Serializes dictionary to `<cache_dir>/<key>.json` with expiration timestamp metadata.
   - `get(key: str) -> Optional[dict[str, Any]]`: Reads cached JSON; returns `None` if absent or if expired (deleting stale file upon detection).
   - `delete(key: str) -> bool`: Removes cache file; returns `True` if existed.
   - `clear() -> int`: Cleans all entries in cache directory and returns count of purged entries.
2. Fixture Lifecycle Architecture (`TestPersistentFileCache(unittest.TestCase)`):
   - `setUpClass(cls)`:
     * Creates an isolated temporary directory via `tempfile.mkdtemp(prefix="cache_test_")`.
     * Instantiates shared cache manager.
   - `tearDownClass(cls)`:
     * Recursively purges temporary directory via `shutil.rmtree` to avoid leaving orphaned test files on disk.
   - `setUp(self)`:
     * Seeds fresh baseline test entries: `cache.set("session_user", {"id": 1, "name": "Alice"})`.
   - `tearDown(self)`:
     * Calls `cache.clear()` ensuring each test starts with a known, isolated state.
   - Dynamic Cleanup via `self.addCleanup`:
     * In a test creating an explicit lock file, registers an inline cleanup callback to guarantee lock deletion even if an assertion errors midway.

Sample Input:
# Run test suite programmatically
suite = unittest.TestLoader().loadTestsFromTestCase(TestPersistentFileCache)
runner = unittest.TextTestRunner(verbosity=0)
result = runner.run(suite)

# Inspect lifecycle verification
is_successful = result.wasSuccessful()
tests_executed = result.testsRun

Expected Output:
Fixture Lifecycle Tests Run: 5
- test_get_existing_baseline: PASSED
- test_expired_entry_purged: PASSED
- test_cache_delete_removes_file: PASSED
- test_cache_clear_purges_all: PASSED
- test_cleanup_callback_executed: PASSED
All Fixture Tests Passed: True
Temporary Directory Cleared Post-Class: Verified

Constraints & Edge Cases:
- Tests must never pollute repository directories; all files must reside in `tempfile.gettempdir()`.
- Expired entries must be verified with artificial clock manipulation or low TTL (`ttl=0.01`).
- Failure of a single test must not prevent `tearDown` or `tearDownClass` from running.
