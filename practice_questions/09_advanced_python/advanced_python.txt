Question 1 (Easy):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that designs a custom cyclical stream iterator `RingBufferIterator`
demonstrating Python's iterator protocol (`__iter__`, `__next__`, `StopIteration`)
alongside the two-argument sentinel invocation of `iter(callable, sentinel)`:
1. Custom Iterator Class Protocol:
   - `__init__(self, items: list[object], max_cycles: int = 1)`:
     * Stores a copy of `items` and tracks total repeat cycles.
     * Rejects empty `items` with `ValueError("Ring buffer items cannot be empty")`.
     * Tracks current element index and completed cycles.
   - `__iter__(self) -> "RingBufferIterator"`:
     * Returns `self` so instances can be passed directly into `for` loops and iterator tools.
   - `__next__(self) -> object`:
     * Returns the current item and advances the cursor.
     * When reaching the end of `items`, wraps back to index 0 and advances completed cycle count.
     * When completed cycles reach `max_cycles`, immediately raises `StopIteration`.
2. Two-Argument Sentinel `iter()` Utility:
   - `read_stream_until_sentinel(source_callable: Callable, sentinel_value: object) -> list`:
     * Uses Python's built-in `iter(source_callable, sentinel_value)` to consume items from a callable
       until it produces `sentinel_value`.
     * Collects and returns the sequence of yielded values prior to the sentinel.

Sample Input:
# Test A: Custom Ring Buffer Iterator
buffer = RingBufferIterator(["TASK_A", "TASK_B", "TASK_C"], max_cycles=2)
collected = list(buffer)

# Test B: Sentinel Iteration
numbers = [10, 20, 30, -1, 40, 50]
iterator_src = iter(numbers)
def read_next():
    return next(iterator_src, -1)

stream_result = read_stream_until_sentinel(read_next, sentinel_value=-1)

Expected Output:
Ring Buffer Iteration (2 complete cycles):
['TASK_A', 'TASK_B', 'TASK_C', 'TASK_A', 'TASK_B', 'TASK_C']

Sentinel Stream Output (stopped at sentinel -1):
[10, 20, 30]

Post-Exhaustion Check:
Invoking next(buffer) after completion raises StopIteration.

Constraints & Edge Cases:
- An iterator must return `self` from `__iter__()`.
- When `max_cycles <= 0`, `__next__()` must immediately raise `StopIteration`.

Problem Statement:
Write a Python program that designs an enterprise endpoint security and observability decorator suite
demonstrating closures, metadata preservation via `@functools.wraps`, and decorator chaining evaluation order:
1. Performance Metrics Decorator `@track_latency`:
   - Maintains an internal metrics dictionary: `{"call_count": int, "total_time": float}`.
   - Measures execution duration using `time.perf_counter()`.
   - Uses `@functools.wraps(func)` to ensure the wrapped function retains its original `__name__` and `__doc__`.
   - Invokes target function, increments count, accumulates time, and returns the original function's result.
2. Parameterized RBAC Security Decorator `@require_role(allowed_roles: set[str])`:
   - Accepts a set of permitted role strings.
   - Wraps the target function: inspects incoming keyword argument `caller_role`.
   - If `caller_role` not in `allowed_roles`, raises `PermissionError(f"Access forbidden: Role '{caller_role}' is not in {allowed_roles}")`.
3. Chained Decorator Execution Order Demonstration:
   - Decorate an administrative function:
     ```python
     @track_latency
     @require_role({"ADMIN", "SUPERUSER"})
     def purge_expired_sessions(caller_role: str, max_age_days: int) -> int:
         """Purges expired user sessions from system storage."""
         return 42
     ```
   - Demonstrate decorator chaining semantics:
     * Decoration occurs bottom-up: `@require_role` wraps `purge_expired_sessions`, then `@track_latency` wraps that result.
     * Execution occurs top-down: `@track_latency` timer starts first, then `@require_role` validates permissions.
   - Demonstrate metadata preservation:
     * `purge_expired_sessions.__name__ == "purge_expired_sessions"`
     * `purge_expired_sessions.__doc__ == "Purges expired user sessions from system storage."`

Sample Input:

# Test 2: Unauthorized invocation

Expected Output:
Purged Sessions Count: 42
Latency Metrics: {'call_count': 1, 'total_time': 0.000...}
Function Name Verified: 'purge_expired_sessions'
Function Docstring Verified: 'Purges expired user sessions from system storage.'
Caught Security Violation: Access forbidden: Role 'GUEST' is not in {'ADMIN', 'SUPERUSER'}

Constraints & Edge Cases:
- Parameterized decorators must use a 3-tier function closure (`def decorator(args): def wrapper_outer(func): def inner(*a, **kw): ...`).
- When an unauthorized access exception is raised, the inner wrapped business logic must never execute.

Problem Statement:
Write a Python program that designs a class-based rate-limiting and retry decorator
`RateLimitedRetry` using `__init__`, `__call__`, and instance-level state tracking:
1. Class Decorator Architecture:
   - `__init__(self, max_retries: int = 3, max_calls_per_second: int = 5, backoff_base: float = 0.05)`:
     * Stores configuration parameters.
     * Initializes state attributes:
       - `self.call_timestamps = collections.deque()` (sliding window of epoch timestamps)
       - `self.total_calls: int = 0`
       - `self.total_retries: int = 0`
   - `__call__(self, func: Callable) -> Callable`:
     * Accepts the target function and returns an inner wrapper function decorated with `@functools.wraps(func)`.
     * Attaches `wrapper.decorator_instance = self` so external callers can inspect instance metrics.
2. Sliding Window Rate Limiting:
   - Inside wrapper, records `now = time.time()`.
   - Evicts timestamps from `self.call_timestamps` that are older than 1.0 second (`now - t > 1.0`).
   - If `len(self.call_timestamps) >= self.max_calls_per_second`, raises
     `RuntimeError(f"Rate limit exceeded: Maximum {self.max_calls_per_second} calls/sec allowed")`.
   - Records current timestamp and increments `self.total_calls`.
3. Retry Mechanism with Exponential Backoff:
   - Executes target function.
   - If a transient exception occurs, increments `self.total_retries` and retries up to `max_retries`
     with delay `backoff_base * (2 ** attempt)`.
   - If all retries fail, propagates the final exception.

Sample Input:
@RateLimitedRetry(max_retries=2, max_calls_per_second=3, backoff_base=0.01)
def fetch_api_data(query_id: int, simulate_failure: bool = False):
    """Fetches remote data payload."""
    if simulate_failure:
        raise ConnectionResetError("Remote server closed socket prematurely")
    return {"id": query_id, "data": "OK"}

# Test 1: Successful Call
res1 = fetch_api_data(101)

# Test 2: Rate Limit Violation (4 calls rapidly when limit is 3/sec)
try:
    for i in range(5):
        fetch_api_data(200 + i)
except RuntimeError as err:
    print("Caught Limit Breach:", err)

# Test 3: Inspect Decorator Instance State
stats = fetch_api_data.decorator_instance

Expected Output:
Successful Fetch: {'id': 101, 'data': 'OK'}
Caught Limit Breach: Rate limit exceeded: Maximum 3 calls/sec allowed
Decorator State:
- Total Calls Tracked: 4
- Total Retries Tracked: 0
- Function Name Preserved: 'fetch_api_data'

Constraints & Edge Cases:
- Using a class as a decorator with arguments requires `__init__` to accept the arguments, and `__call__` to accept the function.
- Time window pruning must happen before checking capacity to allow burst resets after 1 second of inactivity.

Problem Statement:
Write a Python program that designs an environment variable and I/O stream sandbox context manager
`ExecutionSandbox` using the `__enter__` and `__exit__` dunder protocols to safely isolate system state:
1. Environment Sandboxing Protocol:
   - `__init__(self, env_overrides: dict[str, str], capture_stdout: bool = False)`:
     * Stores incoming key-value environment variable overrides.
     * Initializes internal storage for previous environment state: `self._previous_env = {}`.
     * Initializes an in-memory buffer `self.captured_output = io.StringIO()` if `capture_stdout` is True.
   - `__enter__(self) -> "ExecutionSandbox"`:
     * Backs up original values for all keys in `env_overrides`:
       - If key exists in `os.environ`, stores `(key, os.environ[key])`.
       - If key is new to `os.environ`, records `(key, None)`.
     * Applies all `env_overrides` to `os.environ`.
     * If `capture_stdout` is True, redirects `sys.stdout` to `self.captured_output`.
     * Returns `self`.
   - `__exit__(self, exc_type, exc_val, exc_tb) -> bool`:
     * If `capture_stdout` was enabled, restores original `sys.stdout`.
     * Reverts all environment variables back to their exact previous state:
       - For previously present keys, restores original value.
       - For newly created keys, deletes them via `os.environ.pop(key, None)`.
     * Guarantees complete cleanup even if an exception is raised inside the block.
2. Nested Scope Demonstration:
   - Test nesting two sandbox instances where the inner sandbox temporarily overrides a variable
     already modified by the outer sandbox, proving that each layer restores its predecessor state cleanly.

Sample Input:
os.environ["APP_ENV"] = "production"
os.environ["API_KEY"] = "prod-secret-999"

with ExecutionSandbox(env_overrides={"APP_ENV": "staging", "NEW_FLAG": "ENABLED"}, capture_stdout=True) as sandbox:
    print("Executing staging dry run...")
    current_env = os.environ.get("APP_ENV")
    new_flag = os.environ.get("NEW_FLAG")

    # Nested sub-scope:
    with ExecutionSandbox(env_overrides={"APP_ENV": "testing"}):
        nested_env = os.environ.get("APP_ENV")

    post_nested_env = os.environ.get("APP_ENV")

post_sandbox_env = os.environ.get("APP_ENV")
is_new_flag_cleaned = "NEW_FLAG" not in os.environ
stdout_result = sandbox.captured_output.getvalue().strip()

Expected Output:
Inside Sandbox: APP_ENV = 'staging', NEW_FLAG = 'ENABLED'
Inside Nested:  APP_ENV = 'testing'
After Nested:   APP_ENV = 'staging' (Cleanly restored to outer scope)
Captured Stdout: 'Executing staging dry run...'

Post-Sandbox Verification:
- APP_ENV: 'production' (Fully restored)
- NEW_FLAG in os.environ: False (Newly created key purged)
- sys.stdout redirected back to system terminal: True

Constraints & Edge Cases:
- `__exit__` must ensure original `sys.stdout` is restored even if unhandled exceptions escape the `with` block.
- Environment variables must be string types per OS requirements.

4. Domain Deduplication (Set Comprehension):

Problem Statement:
Write a Python program that designs an enterprise log parsing and PII redaction engine
`SecurityLogAnalyzer` leveraging Python's `re` module with named capture groups and `re.VERBOSE`:
1. Structured Log Parser with Verbose Regex (`re.VERBOSE`):
   - Compile a comprehensive regex pattern with named groups to parse server log entries:
     ```python
     LOG_PATTERN = re.compile(r"""
         ^\[(?P<timestamp>\d{4}-\d{2}-\d{2}\s\d{2}:\d{2}:\d{2})\]\s+
         \[(?P<level>INFO|WARNING|ERROR|CRITICAL)\]\s+
         \[(?P<client_ip>(?:\d{1,3}\.){3}\d{1,3})\]\s+
         User<(?P<username>[\w\-]+)>:\s+
         (?P<message>.*)$
     """, re.VERBOSE | re.MULTILINE)
     ```
   - `parse_log_dump(raw_text: str) -> list[dict]`:
     * Uses `LOG_PATTERN.finditer(raw_text)` to extract a list of matched records via `match.groupdict()`.
2. PII Redaction & Data Sanitization via `re.sub`:
   - `redact_sensitive_data(message_text: str) -> str`:
     * Credit Card Masking: Matches 16-digit cards formatted `\b(?P<c1>\d{4})[- ]?\d{4}[- ]?\d{4}[- ]?(?P<c4>\d{4})\b`.
       Replaces with `\g<c1>-XXXX-XXXX-\g<c4>`.
     * Social Security / ID Redaction: Matches `\b\d{3}-\d{2}-\d{4}\b` and replaces with `***-**-****`.
     * Email Obfuscation: Uses a substitution callback function (`def mask_email(m): ...`)
       turning `"john.doe@company.org"` into `"j***e@company.org"`.
3. URL Query Parameter Token Extractor:
   - `extract_query_parameters(url: str) -> dict[str, str]`:
     * Uses regex matching `[?&](?P<key>[^=&#]+)=(?P<val>[^&#]+)` to parse URL parameters into a dictionary.

Sample Input:
analyzer = SecurityLogAnalyzer()

sample_logs = """[2026-10-25 14:30:15] [INFO] [192.168.1.100] User<dev_lead>: Query user profile with email admin@corp.io
[2026-10-25 14:32:00] [ERROR] [10.0.0.5] User<billing_agent>: Failed payment for card 4111-2222-3333-4444 with SSN 123-45-6789"""

parsed_records = analyzer.parse_log_dump(sample_logs)
sanitized_msg = analyzer.redact_sensitive_data(parsed_records[1]["message"])
query_params = analyzer.extract_query_parameters("https://api.corp.net/v1/search?tenant=acme&filter=active&page=2")

Expected Output:
Parsed 2 Log Records:
Record 1: {'timestamp': '2026-10-25 14:30:15', 'level': 'INFO', 'client_ip': '192.168.1.100', 'username': 'dev_lead', ...}
Record 2: {'timestamp': '2026-10-25 14:32:00', 'level': 'ERROR', 'client_ip': '10.0.0.5', 'username': 'billing_agent', ...}

Sanitized Message:
"Failed payment for card 4111-XXXX-XXXX-4444 with SSN ***-**-****"

Extracted Query Parameters:
{'tenant': 'acme', 'filter': 'active', 'page': '2'}

Constraints & Edge Cases:
- Invalid or corrupted log lines that fail to match the strict regex must be ignored or logged as malformed.
- IP addresses with octets > 255 (e.g. `999.999.999.999`) should be validated either in regex or post-validation.
