Question 1 (Easy):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that performs list slicing, step indexing, and in-place slice
assignments on an array of integers:
1. Extraction via Slicing:
   - Extract the first 4 elements using a slice.
   - Extract the last 3 elements using negative indexing.
   - Extract all elements at even indices (index 0, 2, 4, ...).
   - Reverse the entire list using slicing with a negative step.
2. In-Place Slice Mutation:
   - Replace the middle slice (from index 2 up to index 5, exclusive) with three new
     replacement values: [999, 888, 777].
   - Delete elements at odd indices (indices 1, 3, 5, ...) using `del my_list[1::2]`.

Sample Input:
initial_list = [10, 20, 30, 40, 50, 60, 70, 80]

Expected Output:
First 4 Elements: [10, 20, 30, 40]
Last 3 Elements: [60, 70, 80]
Even Indices: [10, 30, 50, 70]
Reversed List: [80, 70, 60, 50, 40, 30, 20, 10]
After Slice Replacement [2:5] = [999, 888, 777]:
[10, 20, 999, 888, 777, 60, 70, 80]
After Deleting Odd Indices:
[10, 999, 777, 70]

Constraints & Edge Cases:
- Perform slice modifications in-place on the original list object where specified.
- The input list will contain at least 6 integer elements.
- Do not use copy loops; leverage Python slice syntax exclusively.

Question 2 (Easy):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that manages a dynamic score registry using built-in list
mutation methods (append, extend, insert, remove, pop, index, count, sort, reverse):
1. Ingestion:
   - Initialize an empty list `roster = []`.
   - Use `append()` to add ("Alice", 92) and ("Bob", 85).
   - Use `extend()` to batch-add [("Charlie", 100), ("Diana", 78), ("Evan", 100)].
2. Positional Insertion & Removal:
   - Use `insert()` to add a late entry ("Fiona", 88) at index 1.
   - Use `remove()` to remove the tuple ("Diana", 78) from the registry.
   - Use `pop()` to remove and capture the last entry in the list.
3. Querying & Inspection:
   - Extract only the numerical scores into a separate list.
   - Use `count()` to find the frequency of scores equal to 100.
   - Use `index()` to find the position of the first entry with score 92.
4. In-Place Ordering:
   - Sort the remaining entries in-place in descending order of score using `roster.sort(key=...)`.
   - Reverse the list in-place using `roster.reverse()`.

Sample Input:
Initial submissions: [("Alice", 92), ("Bob", 85)]
Batch additions: [("Charlie", 100), ("Diana", 78), ("Evan", 100)]
Late insertion at index 1: ("Fiona", 88)

Expected Output:
Roster after insertions and removals:
[('Alice', 92), ('Fiona', 88), ('Bob', 85), ('Charlie', 100)]
Popped Entry: ('Evan', 100)
Count of Perfect 100 Scores: 1
Index of Alice (Score 92): 0
Sorted Descending by Score:
[('Charlie', 100), ('Alice', 92), ('Fiona', 88), ('Bob', 85)]
Reversed (Ascending):
[('Bob', 85), ('Fiona', 88), ('Alice', 92), ('Charlie', 100)]

Constraints & Edge Cases:
- Methods must mutate the list in-place without creating intermediate copy lists
  (except for the query projection).
- Use `remove()` safely by confirming membership first if an item might not exist.

Question 3 (Easy to Intermediate):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that utilizes standard tuples and `collections.namedtuple`
to build an immutable geospatial navigation system:
1. Named Tuple Definition:
   - Create a `Waypoint` namedtuple with fields: `name`, `latitude`, `longitude`, `elevation_m`.
   - Instantiate three waypoints: "Alpha", "Bravo", and "Charlie".
   - Access attributes using both dot notation (`pt.latitude`) and positional indexing (`pt[1]`).
2. Immutability Verification:
   - Demonstrate that tuples are immutable by catching the `AttributeError` raised
     when attempting to modify `point.latitude = 45.0`.
3. Composite Dictionary Keys:
   - Use raw 2-element tuples `(latitude, longitude)` as dictionary keys to map
     coordinates to localized weather conditions (e.g., `(37.77, -122.41): "Foggy"`).
   - Demonstrate why lists cannot be used as dictionary keys by catching `TypeError: unhashable type: 'list'`.
4. Tuple Packing, Unpacking & Arithmetic:
   - Compute the straight-line coordinate distance between consecutive waypoints.
   - Concatenate two route tuples using `+` and repeat an alert tuple using `*`.

Sample Input:
Waypoints:
- "Alpha": lat=37.7749, lon=-122.4194, elevation=15.0
- "Bravo": lat=37.7833, lon=-122.4167, elevation=22.5
- "Charlie": lat=37.7900, lon=-122.4000, elevation=8.0

Expected Output:
Waypoint Alpha: Waypoint(name='Alpha', latitude=37.7749, longitude=-122.4194, elevation_m=15.0)
Positional Access: Name='Alpha', Elevation=15.0 m
Immutability Verified: Caught AttributeError on attempted reassignment.
Dictionary Key Lookup for (37.77, -122.42): "Clear Sky"
Unhashable List Key Verified: Caught TypeError on list dictionary key.
Total Route Waypoint Count: 3 waypoints

Constraints & Edge Cases:
- Latitude must be between -90.0 and 90.0; longitude between -180.0 and 180.0.
- Namedtuples must come from standard library `collections.namedtuple`.
- Unhashable type exceptions must be caught and handled cleanly.

Question 4 (Easy to Intermediate):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that evaluates an enterprise Role-Based Access Control (RBAC)
permission matrix using Python set operations (union |, intersection &, difference -,
symmetric difference ^, subset <=, superset >=, and isdisjoint):
1. Given three role permission sets:
   - `admin_perms`: {"read", "write", "delete", "deploy", "audit", "manage_users"}
   - `dev_perms`: {"read", "write", "deploy", "debug"}
   - `auditor_perms`: {"read", "audit", "export_logs"}
2. Compute the following security audit sets using operator syntax:
   - Shared Permissions: Privileges held by BOTH dev and auditor (`dev & auditor`).
   - Developer-Exclusive Permissions: Privileges held by dev but NOT auditor (`dev - auditor`).
   - Divergent Permissions: Privileges held by dev OR auditor, but NOT both (`dev ^ auditor`).
   - Total System Capabilities: All unique permissions across all roles (`admin | dev | auditor`).
3. Structural Relationship Audits:
   - Verify if `dev_perms` is a subset of `admin_perms` (`dev <= admin`). If not, identify
     the rogue permissions not present in the admin role (`dev - admin`).
   - Given a guest role `guest_perms = {"guest_login", "browse"}`, test if it is completely
     disjoint from `admin_perms` using `.isdisjoint()`.
4. In-Place Mutation:
   - Modify a copy of `dev_perms` using `.intersection_update(auditor_perms)` to retain only
     read-only capabilities.

Sample Input:
admin_perms = {"read", "write", "delete", "deploy", "audit", "manage_users"}
dev_perms = {"read", "write", "deploy", "debug"}
auditor_perms = {"read", "audit", "export_logs"}
guest_perms = {"guest_login", "browse"}

Expected Output:
Shared Dev & Auditor: {'read'}
Developer-Exclusive: {'deploy', 'write', 'debug'}
Divergent Privileges (Symmetric Diff): {'deploy', 'write', 'audit', 'export_logs', 'debug'}
Total Unique System Privileges: 8 permissions
Is Dev a Subset of Admin: False (Rogue Permissions: {'debug'})
Is Guest Disjoint from Admin: True

Constraints & Edge Cases:
- Use set operator syntax (| , &, -, ^) and method equivalents interchangeably.
- Result sets must be unordered and strictly deduplicated.

Question 5 (Intermediate):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that processes and canonicalizes HTTP request headers
using dictionary operations and dictionary view objects:
1. Header Key Normalization:
   - Accept a raw dictionary of HTTP headers with inconsistent casing (e.g.,
     "Content-Type", "AUTHORIZATION", "X-Request-Id").
   - Construct a normalized dictionary where all header keys are strictly lowercase.
2. Dynamic Dictionary Views:
   - Obtain view objects: `.keys()`, `.values()`, and `.items()`.
   - Add a new header `"x-forwarded-for": "10.0.0.1"` and demonstrate that the existing
     view objects reflect this addition dynamically without re-assignment.
3. Fast Key Membership Verification:
   - Perform O(1) membership checks to verify that mandatory security headers
     ("authorization" and "content-type") are present.
4. Dictionary Merging with the Union Operator (|):
   - Given a dictionary of default proxy headers `defaults = {"user-agent": "Proxy/1.0", "accept": "*/*"}`:
   - Merge `defaults` and the client headers using the Python 3.9+ `|` operator,
     guaranteeing that client-specified headers override defaults.

Sample Input:
raw_headers = {
    "Content-Type": "application/json",
    "AUTHORIZATION": "Bearer token_xyz_123",
    "User-Agent": "MobileClient/2.4",
    "X-Correlation-ID": "corr-98765"
}
defaults = {
    "user-agent": "InternalGateway/1.0",
    "accept": "application/json",
    "cache-control": "no-cache"
}

Expected Output:
Normalized Headers:
{
    'content-type': 'application/json',
    'authorization': 'Bearer token_xyz_123',
    'user-agent': 'MobileClient/2.4',
    'x-correlation-id': 'corr-98765'
}
Security Headers Present:
- authorization: True
- content-type: True
Merged Production Headers (Client overrides defaults):
- user-agent: 'MobileClient/2.4'
- accept: 'application/json'
- cache-control: 'no-cache'
- content-type: 'application/json'

Constraints & Edge Cases:
- Headers must be matched case-insensitively via lowercase normalization.
- Dictionary merge must use Python 3.9+ union syntax (`dict_a | dict_b`).
