Question 1 (Easy):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that accepts three distinct values representing a person's
first name, age, and hourly wage. Store them in appropriately typed variables
(string, integer, and float). Determine and print the data type of each variable,
and compute their annual salary assuming a standard 2080-hour work year.

Sample Input:
First Name: "Elena"
Age: 28
Hourly Wage: 34.50

Expected Output:
Variable 'first_name' has type <class 'str'> with value 'Elena'
Variable 'age' has type <class 'int'> with value 28
Variable 'hourly_wage' has type <class 'float'> with value 34.5
Calculated Annual Salary for Elena: $71,760.00

Constraints & Edge Cases:
- Age must be a positive integer.
- Hourly wage must be non-negative.
- Format the salary with two decimal places and comma separators for thousands.

Question 2 (Easy):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that takes a list of heterogeneous raw string inputs
(such as data read from a CSV or web form) and performs safe type conversion:
- If the string represents an integer, convert it to int.
- If it contains a decimal point and represents a valid floating-point number,
  convert it to float.
- If it is case-insensitively "true" or "false", convert it to a boolean.
- If it cannot be converted to any of the above, retain it as a string.
Count how many elements of each type were successfully identified and compute
the sum of all numeric values (integers + floats).

Sample Input:
raw_data = ["42", "3.14159", "True", "hello", "-18", "FALSE", "100.5", "Python3"]

Expected Output:
Parsed types count:
- int: 2 (values: 42, -18)
- float: 2 (values: 3.14159, 100.5)
- bool: 2 (values: True, False)
- str: 2 (values: 'hello', 'Python3')
Total numeric sum: 127.64159

Constraints & Edge Cases:
- Handle negative numbers (e.g. "-18", "-0.75").
- String "True" or "false" must be converted to boolean, not treated as plain string.
- Do not raise unhandled ValueError exceptions during conversion.

Question 3 (Easy to Intermediate):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that performs compound interest calculation and currency
denomination breakdown:
1. Given Principal (P), annual interest rate (r in percent), compounding
   frequency per year (n), and time period in years (t), calculate the total
   accrued amount using the formula:
       A = P * (1 + r / (100 * n)) ** (n * t)
2. Determine the total interest earned (A - P).
3. Using integer division (//) and modulo (%) operators, break down the whole-dollar
   portion of the interest earned into the minimum number of currency bills:
   $100, $50, $20, $10, $5, and $1.

Sample Input:
Principal: 5000.00
Annual Rate (%): 6.5
Compounding Frequency (n): 4 (Quarterly)
Years (t): 3

Expected Output:
Total Accrued Amount: $6,066.86
Total Interest Earned: $1,066.86
Whole Dollar Interest: $1066
Currency Breakdown:
- $100 bills: 10
- $50 bills: 1
- $20 bills: 0
- $10 bills: 1
- $5 bills: 1
- $1 bills: 1

Constraints & Edge Cases:
- All inputs must be non-negative; n and t must be strictly positive.
- Do not use floating-point modulo for bill distribution; cast the whole-dollar
  portion to an integer before computing bill counts.

Question 4 (Intermediate):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that performs string slicing, indexing, and data masking
on sensitive records:
1. Given an email string, slice and extract the local part (before '@') and the
   domain name (after '@').
2. Mask the local part: keep the first and last character visible, replacing all
   intermediate characters with asterisks '*' of the exact same length.
   If the local part has 2 or fewer characters, retain only the first character
   followed by a single '*'.
3. Given an encoded transaction ID string formatted as "TXN-YYYYMMDD-SERIAL",
   use slice indexing to extract the year, month, day, and serial number.
4. Reverse the serial number using negative stride slicing [::-1].

Sample Input:
email = "alexander.dev@example.org"
transaction_id = "TXN-20261022-987654"

Expected Output:
Email Local: "alexander.dev"
Email Domain: "example.org"
Masked Email: "a***********v@example.org"
Transaction Year: "2026", Month: "10", Day: "22"
Serial Number: "987654"
Reversed Serial: "456789"

Constraints & Edge Cases:
- Assume valid standard email structure containing exactly one '@'.
- Handle short usernames cleanly without index out-of-range errors.
- Slicing operations must use slice syntax [start:stop:step] rather than regex.

Question 5 (Intermediate):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that implements a multi-tier security authorization evaluator
using logical and comparison operators (and, or, not, is, ==):
1. A user session is represented by:
   - role: str ("admin", "auditor", "viewer")
   - is_active: bool
   - mfa_verified: bool
   - failed_attempts: int
   - is_internal_ip: bool
2. Access is GRANTED if and only if:
   - The user account is strictly active (is_active is True), AND
   - failed_attempts is strictly less than 3, AND
   - EITHER:
     a) role == "admin" and mfa_verified is True, OR
     b) role in ("auditor", "viewer") and (is_internal_ip or mfa_verified).
3. Demonstrate Python's short-circuit evaluation behavior by ordering conditions
   such that inactive users or locked accounts fail immediately without checking
   network or role status.
4. Distinguish between identity ('is True') and truthy equality ('== 1').

Sample Input:
session_1 = {"role": "admin", "is_active": True, "mfa_verified": True, "failed_attempts": 0, "is_internal_ip": False}
session_2 = {"role": "auditor", "is_active": True, "mfa_verified": False, "failed_attempts": 4, "is_internal_ip": True}
session_3 = {"role": "viewer", "is_active": True, "mfa_verified": False, "failed_attempts": 1, "is_internal_ip": True}

Expected Output:
Session 1 Access: GRANTED (Reason: Admin with verified MFA)
Session 2 Access: DENIED (Reason: Account locked due to excessive failed attempts)
Session 3 Access: GRANTED (Reason: Viewer from trusted internal IP)

Constraints & Edge Cases:
- Account with failed_attempts >= 3 must be denied regardless of other privileges.
- Inactive accounts must be immediately denied.
- Do not use loops or complex external libraries; use compound boolean expressions.
