Question 1 (Easy):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that designs a `BankAccount` class to model basic financial
account lifecycle and transaction operations:
1. Class Definition & Initialization:
   - Implement `__init__(self, account_holder: str, initial_balance: float = 0.0)`:
   - Store instance attributes: `account_holder`, `balance`, and a unique generated
     `account_number` string (e.g. "ACC-1001").
   - Reject negative initial balances by raising a `ValueError`.
2. Account Transactions:
   - `deposit(amount: float) -> float`: Deposit funds; amount must be positive.
     Return the updated balance.
   - `withdraw(amount: float) -> float`: Withdraw funds; amount must be positive and
     cannot exceed current balance. If insufficient funds, raise a `ValueError("Insufficient funds")`.
3. String Representation:
   - Implement `__str__(self) -> str` returning a user-friendly summary:
     `"BankAccount(Holder: <name>, Account#: <num>, Balance: $<bal>)"`.

Sample Input:
account = BankAccount("Alice Smith", 500.0)
account.deposit(250.0)
account.withdraw(120.0)
account.withdraw(700.0)  # Attempt overdraft

Expected Output:
Account Created: BankAccount(Holder: Alice Smith, Account#: ACC-1001, Balance: $500.00)
After Deposit ($250.00): Balance = $750.00
After Withdrawal ($120.00): Balance = $630.00
Overdraft Attempt ($700.00):
Caught Expected Error: ValueError("Insufficient funds")

Constraints & Edge Cases:
- Deposit and withdrawal amounts must be strictly positive floats (> 0).
- Initial balance must be >= 0.0.
- All monetary amounts should format with 2 decimal places.

Question 2 (Easy):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that designs a `CloudServerNode` class to illustrate the
operational distinctions between class variables and instance variables:
1. Shared Class Variables:
   - Maintain class-level state:
     * `total_active_nodes = 0` (tracks count of currently operational nodes)
     * `cluster_datacenter = "us-east-1"` (default shared datacenter region)
     * `node_registry = []` (list referencing all active node instances)
2. Instance Attributes:
   - `__init__(self, node_id: str, cpu_cores: int, ram_gb: int)`:
   - Store instance-specific attributes: `node_id`, `cpu_cores`, `ram_gb`, `is_online = True`.
   - Automatically increment `CloudServerNode.total_active_nodes` and register `self`.
3. Instance Decommissioning:
   - Implement `terminate(self)`:
   - Sets `is_online = False`, decrements `total_active_nodes`, and removes `self` from `node_registry`.
4. Class Attribute Shadowing Gotcha:
   - Rebind `node1.cluster_datacenter = "ap-south-1"` on an individual instance.
   - Prove that this creates an instance-level attribute that shadows the class variable for `node1`,
     while `CloudServerNode.cluster_datacenter` and other nodes remain unchanged.
   - Mutate the shared class variable via `CloudServerNode.cluster_datacenter = "eu-central-1"`
     and verify that unshadowed instances reflect the change immediately.

Sample Input:
node_a = CloudServerNode("node-01", 8, 32)
node_b = CloudServerNode("node-02", 16, 64)
node_c = CloudServerNode("node-03", 4, 16)
node_b.terminate()
node_a.cluster_datacenter = "ap-south-1"  # Shadowing

Expected Output:
Initial Cluster Status:
- Active Nodes: 3
- Node IDs: ['node-01', 'node-02', 'node-03']
- Default Region: "us-east-1"

After Terminating node-02:
- Active Nodes: 2
- Node IDs: ['node-01', 'node-03']

Shadowing Verification:
- node_a Region (Instance Override): "ap-south-1"
- node_c Region (Inherited Class Default): "us-east-1"

After Updating Class Region (CloudServerNode.cluster_datacenter = "eu-central-1"):
- node_a Region: "ap-south-1" (Still shadowed)
- node_c Region: "eu-central-1" (Reflects class update)

Constraints & Edge Cases:
- Terminating an already terminated node must raise a `RuntimeError("Node already offline")`.
- `total_active_nodes` must never drop below 0.

Question 3 (Easy-Intermediate):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that implements an `EmployeeRecord` class demonstrating the
distinct roles and implementations of instance methods, `@classmethod` factory methods,
and `@staticmethod` utility functions:
1. Core Class & Instance Attributes:
   - `__init__(self, emp_id: str, name: str, base_salary: float, department: str)`:
     Initializes an employee record. Validates `emp_id` using the static validator.
   - Instance Method:
     * `calculate_annual_bonus(self, performance_multiplier: float) -> float`:
       Computes bonus as `base_salary * (performance_multiplier / 100.0)`.
     * `get_summary(self) -> str`:
       Returns `"Employee[ID: <emp_id>, Name: <name>, Dept: <department>, Base: $<base_salary>]"`.
2. Alternative Constructors with `@classmethod`:
   - `from_csv_row(cls, csv_text: str) -> "EmployeeRecord"`:
     Accepts a comma-delimited string (e.g., `"EMP101,Diana Prince,85000.0,Security"`),
     strips whitespace, casts numeric fields, and returns a new instance.
   - `from_dict(cls, data_dict: dict) -> "EmployeeRecord"`:
     Extracts corresponding keys from a dictionary and returns a new instance.
3. Utility & Validation with `@staticmethod`:
   - `is_valid_emp_id(emp_id: str) -> bool`:
     Validates whether `emp_id` begins with prefix `"EMP-"` followed by exactly 4 digits (e.g., `"EMP-4092"`).
   - `calculate_tax_bracket(annual_income: float) -> str`:
     Returns tax tier: `"TIER_1"` for <= $50,000, `"TIER_2"` for $50,001 - $100,000,
     and `"TIER_3"` for > $100,000. Does not access class or instance state.

Sample Input:
emp1 = EmployeeRecord("EMP-1001", "Alice Vance", 72000.0, "Engineering")
emp2 = EmployeeRecord.from_csv_row("EMP-2002, Bob Martinez , 95000.0 , Data")
emp3 = EmployeeRecord.from_dict({
    "emp_id": "EMP-3003",
    "name": "Charlie King",
    "base_salary": 115000.0,
    "department": "Finance"
})

Expected Output:
Employee 1 Summary: Employee[ID: EMP-1001, Name: Alice Vance, Dept: Engineering, Base: $72000.00]
Employee 1 Bonus (Rating 15%): $10800.00
Employee 2 from CSV: Employee[ID: EMP-2002, Name: Bob Martinez, Dept: Data, Base: $95000.00]
Employee 3 from Dict: Employee[ID: EMP-3003, Name: Charlie King, Dept: Finance, Base: $115000.00]
Tax Bracket for $115000.00: TIER_3
ID Validation Test ("INVALID-99"): False
ID Validation Test ("EMP-4092"): True

Constraints & Edge Cases:
- Invalid `emp_id` in constructor must raise `ValueError("Invalid employee ID format")`.
- CSV strings with leading or trailing whitespace must be properly trimmed.
- Malformed CSV strings with fewer or more than 4 tokens must raise `ValueError("Malformed CSV row")`.

Question 4 (Easy-Intermediate):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that designs a multi-level vehicle rental hierarchy to demonstrate
inheritance, constructor chaining via `super()`, and polymorphic method overriding:
1. Base Class `Vehicle`:
   - `__init__(self, brand: str, model: str, daily_rate: float)`:
     Stores basic vehicle details. Rejects negative or zero daily rates.
   - `calculate_rental(self, days: int) -> float`:
     Returns `daily_rate * days`. Rejects `days <= 0`.
   - `get_specs(self) -> str`:
     Returns `"Vehicle[Brand: <brand>, Model: <model>, Rate: $<daily_rate>/day]"`.
2. Derived Class `ElectricVehicle(Vehicle)`:
   - `__init__(self, brand: str, model: str, daily_rate: float, battery_capacity: float, range_km: int)`:
     Calls `super().__init__(brand, model, daily_rate)` and initializes battery specs.
   - Override `calculate_rental(self, days: int) -> float`:
     Applies a 10% green vehicle discount on base rental cost and adds a flat $15.00 battery prep fee.
   - Method `estimate_recharge_time(self, charger_power_kw: float) -> float`:
     Returns `battery_capacity / charger_power_kw` rounded to 2 decimal places.
3. Multi-level Derived Class `AutonomousElectricVehicle(ElectricVehicle)`:
   - `__init__(self, brand: str, model: str, daily_rate: float, battery_capacity: float, range_km: int, autopilot_version: str)`:
     Chains initialization through `super().__init__(...)` and records autopilot version.
   - Override `calculate_rental(self, days: int) -> float`:
     Calls `super().calculate_rental(days)` and adds an autonomous safety feature surcharge
     of $25.00 per day.
   - Override `get_specs(self) -> str`:
     Extends `super().get_specs()` by appending `" | Battery: <cap>kWh | Range: <range>km | Autopilot: <ver>"`.

Sample Input:
v1 = Vehicle("Toyota", "Corolla", 50.0)
v2 = ElectricVehicle("Tesla", "Model 3", 80.0, 75.0, 500)
v3 = AutonomousElectricVehicle("Waymo-Jaguar", "I-Pace", 120.0, 90.0, 470, "v4.2-Pro")

rental_v1_3days = v1.calculate_rental(3)
rental_v2_3days = v2.calculate_rental(3)
rental_v3_3days = v3.calculate_rental(3)

Expected Output:
Vehicle 1 (3 days): $150.00
Vehicle 2 EV (3 days): $231.00  # (80 * 3 * 0.90) + 15.00
Vehicle 3 Autonomous (3 days): $399.00  # (120 * 3 * 0.90) + 15.00 + (25.00 * 3)
EV Recharge Time at 50kW Charger: 1.5 hours
Autonomous Vehicle Specs: Vehicle[Brand: Waymo-Jaguar, Model: I-Pace, Rate: $120.00/day] | Battery: 75.0kWh | Range: 470km | Autopilot: v4.2-Pro

Constraints & Edge Cases:
- Rental days <= 0 must raise `ValueError("Rental days must be at least 1")`.
- `charger_power_kw <= 0` must raise `ValueError("Charger power must be positive")`.
- Method overrides must properly leverage `super()` rather than duplicating arithmetic.
