Question 1 (Easy):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that creates a text log inspection utility `analyze_server_log(filepath: str) -> dict`:
1. File Navigation & Inspection:
   - Safely open the target file using context management (`with open(..., mode="r", encoding="utf-8")`).
   - Demonstrate cursor positioning using `tell()` and `seek()`:
     * Check initial stream position with `file.tell()` (verifying it is 0).
     * Read the first line using `file.readline()` to inspect header/preview.
     * Rewind the stream cursor back to byte offset 0 using `file.seek(0)`.
2. Metric Parsing & Extraction:
   - Stream through the file line by line:
     * Count total valid non-empty log lines.
     * Track occurrences of log levels: `"INFO"`, `"WARNING"`, `"ERROR"`, and `"CRITICAL"`.
     * Extract client IPv4 addresses (e.g. `"192.168.1.10"`) and collect unique occurrences.
3. Return Summary Dictionary:
   - Return a dictionary with structure:
     `{"total_lines": int, "counts": {"INFO": int, "WARNING": int, "ERROR": int, "CRITICAL": int}, "unique_ips": list[str]}`.

Sample Input:
# Contents of "server.log":
# 2026-10-24 10:00:01 INFO 192.168.1.10 System started
# 2026-10-24 10:00:15 WARNING 10.0.0.5 High memory usage
# 2026-10-24 10:01:22 ERROR 192.168.1.10 Database connection failed
# 2026-10-24 10:02:05 INFO 172.16.0.2 User login success

result = analyze_server_log("server.log")

Expected Output:
Cursor at start: 0
Header preview: '2026-10-24 10:00:01 INFO 192.168.1.10 System started\n'
Cursor reset: 0
Log Analysis Summary:
- Total Lines: 4
- INFO Count: 2
- WARNING Count: 1
- ERROR Count: 1
- CRITICAL Count: 0
- Unique Client IPs: ['10.0.0.5', '172.16.0.2', '192.168.1.10']

Constraints & Edge Cases:
- Missing file must raise `FileNotFoundError("Log file not found")`.
- Empty log files must return `total_lines: 0`, all zero counts, and an empty list of IPs.
- Blank/empty lines or whitespace-only lines in the log must be ignored.

1. Overwrite Protection:
   - Check if `target_filepath` already exists. If it exists and `overwrite is False`,
     raise `FileExistsError(f"Target '{target_filepath}' already exists and overwrite is False")`.
2. Atomic Temporary File Pattern:
   - To guarantee data integrity against partial writes or mid-execution crashes, write all output
     first to a sibling temporary file (e.g., `f"{target_filepath}.tmp"`).
   - Use `try...finally` or equivalent cleanup to guarantee that the `.tmp` staging file is removed
     if an error or exception occurs before completion.
3. Writing Content & Structuring Output:

   - Format and write an audit report header:
     `"=== SYSTEM AUDIT REPORT ==="` and column headers: `"TIMESTAMP | EVENT_ID | SEVERITY | DESCRIPTION\n"`.

   - Flush and sync buffered data to ensure all bytes reach disk before atomic rename.
4. Atomic Promotion:

   - Return the count of audit records written.

# Generated File Content:

TIMESTAMP           | EVENT_ID | SEVERITY | DESCRIPTION
2026-10-24 10:15:00 | EVT-101  | LOW      | Config reloaded
2026-10-24 10:17:30 | EVT-102  | HIGH     | TLS cert expired
2026-10-24 10:20:10 | EVT-103  | CRITICAL | Kernel panic avoided

Overwrite Conflict Test:

- Parent directories for `target_filepath` must be created if they do not exist (`os.makedirs(..., exist_ok=True)`).

Question 3 (Easy-Intermediate):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that designs an append-only transaction ledger utility `LedgerManager`
demonstrating the exact behavioral differences among file open modes (`'x'`, `'a'`, `'r+'`, and `'w+'`):
1. Exclusive File Initialization (`'x'` mode):
   - `init_ledger(filepath: str, initial_tx_capacity: int = 0) -> bool`:
     Opens file using mode `'x'` (exclusive creation). Writes a standardized fixed-width header:
     `"LEDGER_HEADER | TX_COUNT: 00000 | STATUS: ACTIVE       \n"`.
     If the file already exists, catches `FileExistsError` and returns `False` without modifying the file.
2. Appending Transactions (`'a'` mode):
   - `append_transaction(filepath: str, tx_id: str, sender: str, recipient: str, amount: float) -> None`:
     Opens file in mode `'a'` (append). Writes formatted line:
     `f"TX | ID: {tx_id:<8} | FROM: {sender:<12} | TO: {recipient:<12} | AMT: ${amount:>10.2f}\n"`.
     Guarantees that new transactions always write to the end of the file.
3. In-Place Header Mutation (`'r+'` mode):
   - `update_ledger_header(filepath: str, new_tx_count: int, new_status: str) -> None`:
     Opens file using mode `'r+'` (read/write in place without truncating).
     Uses `file.seek(0)` to rewind to the very beginning and overwrites only the 52-character
     header block formatted as:
     `f"LEDGER_HEADER | TX_COUNT: {new_tx_count:05d} | STATUS: {new_status:<12}\n"`.
     Ensures existing appended transaction records below the header remain completely intact.
4. Truncation Hazard Demonstration (`'w+'` mode):
   - Implement a test demonstrating that opening an existing file with mode `'w+'` immediately truncates
     its file size to 0 bytes before any read or write occurs, unlike `'r+'`.

Sample Input:
ledger = LedgerManager()
ledger.init_ledger("vault_ledger.txt")
ledger.append_transaction("vault_ledger.txt", "TX-001", "Alice", "Bob", 250.00)
ledger.append_transaction("vault_ledger.txt", "TX-002", "Charlie", "Diana", 750.50)
ledger.update_ledger_header("vault_ledger.txt", new_tx_count=2, new_status="VERIFIED")

# Test exclusive creation on existing file:
created_again = ledger.init_ledger("vault_ledger.txt")

Expected Output:
Ledger initialized successfully with mode 'x'.
Appended TX-001.
Appended TX-002.
Header updated in-place via mode 'r+' (offset 0).
Attempting re-initialization on existing file: False (Safely blocked)

# Resulting File Content ("vault_ledger.txt"):
LEDGER_HEADER | TX_COUNT: 00002 | STATUS: VERIFIED    
TX | ID: TX-001   | FROM: Alice        | TO: Bob          | AMT: $    250.00
TX | ID: TX-002   | FROM: Charlie      | TO: Diana        | AMT: $    750.50

Constraints & Edge Cases:
- The fixed-width header must match the exact line character length on update to avoid displacing or clipping subsequent lines.
- Updating header on a non-existent file in `'r+'` mode must catch `FileNotFoundError`.

Question 4 (Easy-Intermediate):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that designs a filesystem path inspection and security utility
`ProjectAssetAuditor` using modern object-oriented `pathlib.Path`:
1. Root Path Normalization:
   - `__init__(self, root_directory: str | Path)`:
     Resolves the provided path to its absolute canonical form (`Path(root_directory).resolve()`).
     Validates that the target path exists and is a directory (`root.is_dir()`).
     If non-existent or a file, raises `NotADirectoryError(f"Path '{root}' is not a valid directory")`.
2. Recursive File Discovery & Auditing:
   - `audit_extensions(self, target_extensions: tuple[str, ...]) -> list[dict]`:
     Recursively searches through the root directory tree using `path.rglob("*")`.
     Filters files matching the given extensions (e.g., `(".py", ".json", ".txt")`).
     For each matching regular file (`file.is_file()`), extracts:
     * `relative_path`: Path relative to root (`file.relative_to(self.root)`) as POSIX string.
     * `stem`: File name without suffix.
     * `suffix`: File extension (e.g. `".py"`).
     * `parent_folder`: Immediate parent directory name.
     * `size_bytes`: Integer byte size via `file.stat().st_size`.
3. Mirror Backup Path Generator:
   - `generate_backup_path(self, source_file: Path, backup_root: Path) -> Path`:
     Calculates relative subpath of `source_file` from `self.root`, prepends `backup_root`,
     and appends `".bak"` to the extension (e.g., `"src/app.py"` -> `"backups/src/app.py.bak"`).
4. Path Traversal Security Guard:
   - `safe_resolve_subpath(self, untrusted_relative_path: str) -> Path`:
     Resolves the joined path `(self.root / untrusted_relative_path).resolve()`.
     Verifies that the resolved path is strictly within `self.root` using `is_relative_to(self.root)`.
     If it escapes (e.g., `"../../etc/passwd"`), raises `PermissionError("Path traversal attack detected")`.

Sample Input:
auditor = ProjectAssetAuditor("./workspace/sample_project")
matched_assets = auditor.audit_extensions(target_extensions=(".py", ".txt"))
backup_target = auditor.generate_backup_path(
    Path("./workspace/sample_project/utils/helper.py"),
    Path("./backups")
)

# Traversal exploit simulation:
try:
    auditor.safe_resolve_subpath("../../outside_secret.key")
except PermissionError as err:
    print("Caught Security Violation:", err)

Expected Output:
Auditor Root: /workspace/sample_project
Found 2 matching assets:
1. utils/helper.py | Size: 1048 bytes | Parent: utils
2. config.txt      | Size: 256 bytes  | Parent: sample_project

Backup Destination: backups/utils/helper.py.bak
Caught Security Violation: Path traversal attack detected

Constraints & Edge Cases:
- All returned relative paths must use forward slashes (via `as_posix()`) for cross-platform consistency.
- Paths pointing to symlinks pointing outside the root directory must be caught by traversal checks.

Question 6 (Intermediate):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that designs a transactional file editor context manager `TransactionalFileEditor`
using `__enter__` and `__exit__` dunder methods to guarantee automatic rollback if an error occurs mid-edit:
1. Context Manager Protocol:
   - `__init__(self, filepath: str)`: Stores target path and backup path (`f"{filepath}.bak"`).
   - `__enter__(self) -> "TransactionalFileEditor"`:
     * If the target file exists, creates an exact binary backup copy at `f"{filepath}.bak"`.
     * If the target file does not exist, marks a flag that creation is pending.
     * Returns `self`.
   - `__exit__(self, exc_type, exc_val, exc_tb) -> bool`:
     * If `exc_type is not None` (an unhandled exception occurred within the `with` block):
       - Triggers automatic rollback: restores original file from `.bak` (or deletes target if newly created).
       - Cleans up backup file.
       - Returns `False` to propagate the exception.
     * If `exc_type is None` (block completed successfully):
       - Commits transaction by removing the `.bak` staging file.
2. Editing API on the Context Instance:
   - `write_lines(self, lines: list[str]) -> None`: Overwrites or appends lines to target.
   - `append_text(self, text: str) -> None`: Appends string to the working file.
3. Generator Context Manager with `@contextlib.contextmanager`:
   - Implement `@contextmanager def suppress_and_log_io_errors(logger_tag: str)`:
     Yields execution; if an `OSError` or `FileNotFoundError` occurs, logs error message
     and suppresses the exception so the calling program does not crash.

Sample Input:
# Scenario A: Successful transactional update
with TransactionalFileEditor("config.ini") as editor:
    editor.append_text("timeout = 60\n")
    editor.append_text("retries = 3\n")

# Scenario B: Failed transaction triggers automatic rollback
try:
    with TransactionalFileEditor("config.ini") as editor:
        editor.append_text("corrupted_line = True\n")
        raise RuntimeError("Simulated process crash during file update!")
except RuntimeError as err:
    print("Caught:", err)

Expected Output:
Scenario A:
Backup created at: config.ini.bak
Transaction committed successfully. Backup removed.

Scenario B:
Backup created at: config.ini.bak
Exception encountered: RuntimeError('Simulated process crash during file update!')
Rollback executed: Restored config.ini from config.ini.bak.
Caught: Simulated process crash during file update!
File content verified: Matches pre-transaction state without corrupted_line.

Constraints & Edge Cases:
- Rollback must be completely resilient: original file content and permissions must be restored.
- If backup creation fails in `__enter__`, `__exit__` must not attempt to restore non-existent backup.
