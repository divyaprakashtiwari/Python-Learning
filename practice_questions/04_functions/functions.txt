Question 1 (Easy):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that defines and tests a mathematical utility function
`calculate_cone_properties(radius: float, height: float)`:
1. Positional Parameters & Mathematical Computations:
   - Accept two positive floating-point numbers: `radius` and `height`.
   - Calculate the slant height using the Pythagorean theorem:
         slant_height = sqrt(radius**2 + height**2)
   - Calculate the lateral surface area:
         lateral_area = pi * radius * slant_height
   - Calculate the total surface area:
         total_area = pi * radius * (radius + slant_height)
   - Calculate the volume:
         volume = (1 / 3) * pi * (radius**2) * height
2. Return Values vs Side Effects:
   - The function must return a dictionary of computed metrics rounded to 2 decimal places,
     without performing any `print()` calls inside its body.
   - The caller must format and display the returned dictionary.
3. Input Validation:
   - If either `radius` or `height` is less than or equal to zero, raise a `ValueError`.

Sample Input:
radius = 3.0
height = 4.0

Expected Output:
Cone Properties for r=3.00, h=4.00:
- Slant Height: 5.00
- Lateral Surface Area: 47.12
- Total Surface Area: 75.40
- Volume: 37.70

Constraints & Edge Cases:
- Use `math.pi` and `math.sqrt` from Python's standard `math` module.
- Raise `ValueError("Dimensions must be strictly positive numbers")` if radius <= 0 or height <= 0.
- Ensure the function has no side-effects (does not mutate outer state or print directly).

Question 2 (Easy):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that analyzes and repairs the "mutable default argument" trap
while utilizing default, keyword, and keyword-only arguments:
1. Demonstrating the Mutable Default Trap:
   - Write a function `record_event_flawed(event_id: str, tags=[])`:
   - In the body, append `event_id` to `tags` and return `tags`.
   - Invoke `record_event_flawed("evt_1")` followed by `record_event_flawed("evt_2")`
     without providing the `tags` argument.
   - Demonstrate that the second call unexpectedly returns `['evt_1', 'evt_2']`
     because the default list was evaluated only once at function definition time.
2. Idiomatic Safe Default Pattern:
   - Refactor the function to `record_event_safe(event_id: str, tags=None, *, log_level="INFO", dry_run=False)`:
   - If `tags is None`: initialize a new empty list `tags = []` inside the function body.
   - Enforce that `log_level` and `dry_run` are keyword-only parameters (placed after a bare `*`).
3. Verification:
   - Demonstrate that multiple consecutive invocations of `record_event_safe()` produce
     isolated lists without state leakage.
   - Demonstrate that passing `log_level` as a positional argument raises a `TypeError`.

Sample Input:
Call 1: record_event_flawed("login")
Call 2: record_event_flawed("logout")
Call 3: record_event_safe("purchase", log_level="AUDIT")
Call 4: record_event_safe("refund")

Expected Output:
Flawed Call 1: ['login']
Flawed Call 2: ['login', 'logout'] (Leaked previous invocation state!)

Safe Call 1: ['purchase'] (Tags isolated)
Safe Call 2: ['refund'] (Tags isolated)
Positional Keyword-Only Test:
Caught Expected Error: TypeError("record_event_safe() takes at most 2 positional arguments...")

Constraints & Edge Cases:
- Never use mutable objects (lists, dicts, sets) as default argument values in production code.
- Keyword-only parameters must be strictly guarded using the bare asterisk syntax `*`.
