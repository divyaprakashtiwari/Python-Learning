Question 1 (Easy):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that defines and tests a mathematical utility function
`calculate_cone_properties(radius: float, height: float)`:
1. Positional Parameters & Mathematical Computations:
   - Accept two positive floating-point numbers: `radius` and `height`.
   - Calculate the slant height using the Pythagorean theorem:
         slant_height = sqrt(radius**2 + height**2)
   - Calculate the lateral surface area:
         lateral_area = pi * radius * slant_height
   - Calculate the total surface area:
         total_area = pi * radius * (radius + slant_height)
   - Calculate the volume:
         volume = (1 / 3) * pi * (radius**2) * height
2. Return Values vs Side Effects:
   - The function must return a dictionary of computed metrics rounded to 2 decimal places,
     without performing any `print()` calls inside its body.
   - The caller must format and display the returned dictionary.
3. Input Validation:
   - If either `radius` or `height` is less than or equal to zero, raise a `ValueError`.

Sample Input:
radius = 3.0
height = 4.0

Expected Output:
Cone Properties for r=3.00, h=4.00:
- Slant Height: 5.00
- Lateral Surface Area: 47.12
- Total Surface Area: 75.40
- Volume: 37.70

Constraints & Edge Cases:
- Use `math.pi` and `math.sqrt` from Python's standard `math` module.
- Raise `ValueError("Dimensions must be strictly positive numbers")` if radius <= 0 or height <= 0.
- Ensure the function has no side-effects (does not mutate outer state or print directly).

Question 2 (Easy):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that analyzes and repairs the "mutable default argument" trap
while utilizing default, keyword, and keyword-only arguments:
1. Demonstrating the Mutable Default Trap:
   - Write a function `record_event_flawed(event_id: str, tags=[])`:
   - In the body, append `event_id` to `tags` and return `tags`.
   - Invoke `record_event_flawed("evt_1")` followed by `record_event_flawed("evt_2")`
     without providing the `tags` argument.
   - Demonstrate that the second call unexpectedly returns `['evt_1', 'evt_2']`
     because the default list was evaluated only once at function definition time.
2. Idiomatic Safe Default Pattern:
   - Refactor the function to `record_event_safe(event_id: str, tags=None, *, log_level="INFO", dry_run=False)`:
   - If `tags is None`: initialize a new empty list `tags = []` inside the function body.
   - Enforce that `log_level` and `dry_run` are keyword-only parameters (placed after a bare `*`).
3. Verification:
   - Demonstrate that multiple consecutive invocations of `record_event_safe()` produce
     isolated lists without state leakage.
   - Demonstrate that passing `log_level` as a positional argument raises a `TypeError`.

Sample Input:
Call 1: record_event_flawed("login")
Call 2: record_event_flawed("logout")
Call 3: record_event_safe("purchase", log_level="AUDIT")
Call 4: record_event_safe("refund")

Expected Output:
Flawed Call 1: ['login']
Flawed Call 2: ['login', 'logout'] (Leaked previous invocation state!)

Safe Call 1: ['purchase'] (Tags isolated)
Safe Call 2: ['refund'] (Tags isolated)
Positional Keyword-Only Test:
Caught Expected Error: TypeError("record_event_safe() takes at most 2 positional arguments...")

Constraints & Edge Cases:
- Never use mutable objects (lists, dicts, sets) as default argument values in production code.
- Keyword-only parameters must be strictly guarded using the bare asterisk syntax `*`.

Question 3 (Easy to Intermediate):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that designs a dynamic SQL query string builder function
utilizing variable positional arguments (*args), keyword arguments (**kwargs), and argument unpacking:
1. Function Specification:
   `build_select_query(table_name: str, *columns: str, distinct: bool = False, **where_clauses) -> tuple[str, tuple]`
2. Positional Unpacking (*columns):
   - If `columns` is empty (no positional arguments provided), default to selecting all columns (`*`).
   - If columns are supplied, join them with commas: `"col1, col2, col3"`.
   - If `distinct is True`, prepend `DISTINCT` before the column list.
3. Keyword Filtering (**where_clauses):
   - If `where_clauses` contains items, generate a parameterized `WHERE` clause:
     `" WHERE col1 = ? AND col2 = ?"` (joining criteria with `" AND "`).
   - Collect all filter values into a parameter tuple in identical order.
4. Call-Site Argument Unpacking:
   - Given a list of target columns `target_cols = ["id", "username", "email"]` and a
     filter dictionary `criteria = {"status": "ACTIVE", "role": "ADMIN"}`, invoke
     the function using `*target_cols` and `**criteria` unpacking.

Sample Input:
Call 1: build_select_query("users")
Call 2: build_select_query("orders", "order_id", "total_price", distinct=True, customer_id=42, status="SHIPPED")
Call 3 (via unpacking):
cols = ["first_name", "last_name", "department"]
filters = {"active": True, "location": "NYC"}
build_select_query("employees", *cols, **filters)

Expected Output:
Query 1:
SQL: "SELECT * FROM users;"
Params: ()

Query 2:
SQL: "SELECT DISTINCT order_id, total_price FROM orders WHERE customer_id = ? AND status = ?;"
Params: (42, 'SHIPPED')

Query 3 (Unpacked):
SQL: "SELECT first_name, last_name, department FROM employees WHERE active = ? AND location = ?;"
Params: (True, 'NYC')

Constraints & Edge Cases:
- Parameters must never be interpolated directly into the SQL string to avoid injection.
- Handle zero columns cleanly by defaulting to `*`.

Question 4 (Easy to Intermediate):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that utilizes multiple return values (automatic tuple packing/unpacking),
early return guard clauses, and callable factory functions:
1. Multi-Value Statistical Analyzer:
   - Implement `compute_descriptive_stats(dataset: list[float]) -> tuple`:
   - Early Return Guard: If `dataset` is empty, immediately return `(0, 0.0, 0.0, 0.0, 0.0)`.
   - Otherwise, compute:
     * Count: number of elements
     * Mean: arithmetic average
     * Median: middle value (or average of two middle values if length is even)
     * Variance: sample variance sum((x - mean)**2) / (n - 1) for n > 1 (0.0 if n == 1)
     * Range: max_value - min_value
   - Return all five metrics in a single `return` statement (tuple packing).
   - Unpack the returned tuple into five individual variables at the call site.
2. Function Factory (Returning Callables):
   - Implement a converter factory `make_unit_converter(from_unit: str, to_unit: str)`:
   - Return a specialized conversion function (e.g. converting Celsius to Fahrenheit: `lambda c: c * 9/5 + 32`).
   - If the requested conversion pair is unrecognized, raise a `ValueError`.

Sample Input:
data = [12.5, 14.0, 15.5, 18.0, 20.0, 22.5, 24.0]
c_to_f = make_unit_converter("C", "F")
c_to_k = make_unit_converter("C", "K")

Expected Output:
Dataset Statistics:
- Count: 7
- Mean: 18.07
- Median: 18.00
- Variance: 18.29
- Range: 11.50

Factory Conversion:
- 100.0 C -> F: 212.0 F
- 0.0 C -> K: 273.15 K
Empty Dataset Guard: (0, 0.0, 0.0, 0.0, 0.0)

Constraints & Edge Cases:
- Do not import external statistics libraries (`statistics`, `numpy`); calculate manually.
- Handle datasets of length 0 and length 1 without division-by-zero errors.

Question 5 (Intermediate):
--------------------------------------------------------------------------------
Problem Statement:
Write a Python program that uses anonymous lambda functions as custom evaluation
predicates and ranking keys for sorting and metric extraction:
1. Multi-Criteria Ranking via Lambda:
   - Given a list of financial asset dictionaries:
     `assets = [{"ticker": str, "sector": str, "market_cap_b": float, "pe_ratio": float, "div_yield": float}]`
   - Use `sorted()` with a single `key=lambda x: ...` to sort the assets primarily
     by sector alphabetically (ascending), and secondarily by market capitalization
     descending (highest market cap first within each sector).
2. Extremum Extraction via `min()` and `max()`:
   - Identify the asset with the highest dividend yield using `max()` with a lambda key.
   - Identify the asset with the lowest valuation (P/E ratio) using `min()` with a lambda key.
3. Anonymous Fee Calculator Dispatcher:
   - Construct a dictionary mapping transaction types ("BUY", "SELL", "TRANSFER")
     to anonymous lambda fee calculators:
     * "BUY": fee is 0.1% of principal or $1.00, whichever is greater (`lambda p: max(1.0, p * 0.001)`)
     * "SELL": fee is 0.15% of principal plus $0.50 regulatory fee (`lambda p: p * 0.0015 + 0.50`)
     * "TRANSFER": flat fee of $2.50 (`lambda p: 2.50`)

Sample Input:
assets = [
    {"ticker": "AAPL", "sector": "Technology", "market_cap_b": 3400.0, "pe_ratio": 33.2, "div_yield": 0.55},
    {"ticker": "JNJ",  "sector": "Healthcare", "market_cap_b": 380.0,  "pe_ratio": 24.1, "div_yield": 3.10},
    {"ticker": "MSFT", "sector": "Technology", "market_cap_b": 3100.0, "pe_ratio": 35.8, "div_yield": 0.72},
    {"ticker": "PFE",  "sector": "Healthcare", "market_cap_b": 160.0,  "pe_ratio": 15.4, "div_yield": 5.80}
]

Expected Output:
Sorted Assets (Sector ASC, Market Cap DESC):
1. Healthcare: JNJ ($380.0B)
2. Healthcare: PFE ($160.0B)
3. Technology: AAPL ($3400.0B)
4. Technology: MSFT ($3100.0B)

Highest Dividend Yield: PFE (5.80%)
Lowest P/E Valuation: PFE (15.4)

Transaction Fees for $10,000 Trade:
- BUY Fee: $10.00
- SELL Fee: $15.50
- TRANSFER Fee: $2.50

Constraints & Edge Cases:
- All sorting and extremum selection must be performed using `lambda` functions.
- Principal amounts must be non-negative.
