1. DEFINITION AND EXPLANATION
--------------------------------------------------------------------------------
Real-world Python programming relies heavily on data interchange formats,
network requests, persistence engines, configuration management, and command-line
interfaces.

Core domains covered in this topic:
- JSON (JavaScript Object Notation): Standard text format for serializing
  structured data (objects, arrays, strings, numbers, booleans, null).
- CSV (Comma-Separated Values): Delimited tabular plain-text format for tabular data.
- REST APIs & HTTP Requests: Interacting with web services using the built-in
  urllib.request module (GET, POST, headers, status codes, query encoding).
- Relational Databases with SQLite3: Serverless, transactional ACID-compliant
  embedded database included with Python standard library.
- Data Transformation (ETL): Extracting data from disparate sources, cleaning/transforming
  records, and loading into target datastores.
- Configuration Parsing: Reading and writing INI/configuration files via configparser.
- Web Scraping: Fetching HTML content and extracting tags/data using html.parser or regex.
- Email Validation & Processing: Validating RFC email addresses using regex and building
  MIME email structures via the email module.
- Asynchronous Concurrency with Asyncio: Event loops, coroutines (async/await), tasks,
  and non-blocking concurrent operations via asyncio.
- CLI Argument Parsing: Building production CLI interfaces using argparse.

B. CSV Processing with DictReader and DictWriter:
    import csv

    # Writing CSV with headers:
    records = [
        {"id": 1, "name": "Alice", "score": 95},
        {"id": 2, "name": "Bob", "score": 88}
    ]
    with open("scores.csv", "w", newline="", encoding="utf-8") as f:
        writer = csv.DictWriter(f, fieldnames=["id", "name", "score"])
        writer.writeheader()
        writer.writerows(records)

    # Reading CSV:
    with open("scores.csv", "r", newline="", encoding="utf-8") as f:
        reader = csv.DictReader(f)
        for row in reader:
            print(row["name"], row["score"])

D. SQLite Database CRUD & Transactions:
    import sqlite3

    conn = sqlite3.connect("app.db")
    cursor = conn.cursor()

    # Create table:
    cursor.execute("""
        CREATE TABLE IF NOT EXISTS users (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            username TEXT UNIQUE NOT NULL,
            email TEXT NOT NULL
        )
    """)

    # Parameterized Insert (prevents SQL injection):
    cursor.execute("INSERT INTO users (username, email) VALUES (?, ?)", ("alice", "alice@example.com"))
    conn.commit()

    # Query with fetchall:
    cursor.execute("SELECT id, username, email FROM users WHERE username = ?", ("alice",))
    rows = cursor.fetchall()

    conn.close()

    import asyncio

    async def fetch_data(id: int, delay: float):
        await asyncio.sleep(delay)  # non-blocking asynchronous sleep
        return {"id": id, "status": "completed"}

    async def main():
        # Run concurrent coroutines:

3. COMMON METHODS, FUNCTIONS, AND RULES
--------------------------------------------------------------------------------
- json.dump(obj, fp) / json.load(fp): Directly serializes/deserializes to/from file objects.
- json.dumps(obj) / json.loads(s): Converts between Python dict/list and JSON string.
- csv.DictReader(f) / csv.DictWriter(f, fieldnames): Maps CSV rows to dictionaries.
- newline="" in open() for CSV: Prevents blank extra rows on Windows systems.
- urllib.parse.urlencode(dict): Safely escapes and formats URL query string parameters.
- sqlite3.connect(":memory:"): In-memory SQLite database, ideal for fast unit tests.
- cursor.executemany(sql, seq_of_params): High-performance batch insert/update in SQLite.
- asyncio.run(coro): Runs the entry-point coroutine and manages the event loop lifecycle.
- asyncio.gather(*coros): Runs multiple coroutines concurrently and returns ordered results.
- argparse.ArgumentParser.add_argument(): Defines CLI positional & optional flags.


4. COMMON MISTAKES AND TIPS
--------------------------------------------------------------------------------
- SQL Injection: NEVER use f"SELECT * FROM users WHERE name = '{name}'". Always use
  parameter substitution with `?`: cursor.execute("SELECT * ... WHERE name = ?", (name,)).
- Forgetting conn.commit(): SQLite transactions do not persist changes until explicitly
  committed, or when using `with conn:` context manager.
- Non-serializable JSON types: Standard JSON cannot serialize datetime, sets, or custom classes
  by default. Provide a custom default encoder function: `json.dumps(obj, default=str)`.
- CSV delimiter issues: European CSV files often use semicolons (`;`) instead of commas.
  Use csv.Sniffer().sniff(sample) or specify delimiter=";" when necessary.
- Asyncio blocking calls: Calling time.sleep() or blocking I/O inside an async def function
  freezes the entire event loop. Use asyncio.sleep() or run_in_executor().
- Missing User-Agent header: Many web servers reject HTTP requests lacking a standard User-Agent
  header with a 403 Forbidden error.


5. QUICK REVISION POINTS
--------------------------------------------------------------------------------
- JSON keys must always be strings; JSON uses double quotes (""), never single quotes.
- DictReader uses the first line of CSV as header dictionary keys.
- SQLite ? placeholders automatically handle quotation escaping and data type binding.
- Transactions: Use `with conn:` so commits occur automatically on success and rollbacks on error.
- configparser values are always read as strings; use getint(), getboolean(), getfloat() to cast.
- Async coroutines must be awaited with `await`; calling a coroutine without `await` only creates a coroutine object.
- argparse automatically generates `--help` / `-h` documentation and type-checks CLI arguments.
